 DATA MODEL HIERARCHY
━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━

  INTELLIGENCE TAXONOMY (three persona types, all triggered the same way)
  ──────────────────────────────────────────────────────────────────────
  1. Plain model    source_type="model"
                    Persona.model → AIModel → LiteLLM direct call

  2. Self-made agent source_type="agent", agent.agent_type="internal"
                    Persona.agent → AIAgent → model + MCPServer(s)
                    → pydantic-ai Agent + tool call loop

  3. Online agent   source_type="agent", agent.agent_type="external"
                    Persona.agent → AIAgent.external_url
                    → HTTP/SSE proxy to remote endpoint


  AIModel  (provider, model_id, encrypted api_key, licence_accepted)
      │
      ├── MCPServer[] (optional — attaching MCP makes it an agent)
      │       name, endpoint, transport (stdio|sse|http|websocket), config
      │       is_first_party: bool  (marketplace-owned vs external)
      │       embed_output: bool    (opt-in per tool, first-party only)
      │       multiple MCP servers per agent = multiple capabilities
      │
      └── Persona[] (WHO the AI is)
              name, shadow_user, source_type
              │
              └── Prompt
                      system_prompt
                      context_scope (optional — restricts which contexts to use)
                      output_type   (text|code|chart|html|form|terminal)
                      template_ref  (optional — from PromptTemplate library)

  ChatSession  (per-user, per-topic timed session)
      user       → ForeignKey(User)
      topic      → ForeignKey(Topic)
      personas   → ManyToManyField(Persona)
      expires_at → DateTimeField  (fixed from open time, not rolling)
      created_at → DateTimeField
      UniqueConstraint(user, topic)  — one active session per user per topic

  CompanyAIConfig additions:
      session_timeout_minutes → PositiveIntegerField(default=30)

  PromptTemplate  (growing curated library, platform maintained)
      title, description, system_prompt, output_type, tags

  ContextSource  (attached to a topic)
      type (doc|code), label, content, language
      collection_id (Chroma — returned after embed)
      topic → ForeignKey

  AIRequestLog
      persona, user, topic
      full_prompt (complete messages[] sent to model)
      response    (full model response)
      model_used, tokens_input, tokens_output, tokens_total, cost
      latency_ms, created_at

────────────────────────────────────────────────────────────────────────────────
 FLOW 1 — Add AI Model
────────────────────────────────────────────────────────────────────────────────

  [User]
    │  POST /api/ai-models/
    │  { provider, model_id, api_key, licence_accepted }
    ▼
  [nexus-nucleus]
    ├──► licence_accepted check
    ├──► encrypt api_key
    └──► save PostgreSQL [AIModel]


────────────────────────────────────────────────────────────────────────────────
 FLOW 2 — Attach MCP Servers to Model (optional → model becomes agent)
────────────────────────────────────────────────────────────────────────────────

  [User]
    │  POST /api/ai-models/{id}/mcp-servers/
    │  { name, endpoint, type: stdio|sse, config }
    ▼
  [nexus-nucleus]
    └──► save PostgreSQL [MCPServer → AIModel]

  Note: multiple MCP servers per model allowed
        each MCP server = one set of tool capabilities
        (terminal, SSH, database, API, file system, etc.)
        model WITH MCP servers = agent
        model WITHOUT MCP servers = plain LLM


────────────────────────────────────────────────────────────────────────────────
 FLOW 3 — Add Persona + Prompt
────────────────────────────────────────────────────────────────────────────────

  [User]
    │  POST /api/personas/
    │  { name, ai_model_id, prompt }
    │  prompt.system_prompt → from PromptTemplate library OR custom
    │  prompt.context_scope → optional (restrict which contexts to use)
    │  prompt.output_type  → text|code|chart|html|form
    ▼
  [nexus-nucleus]
    ├──► create shadow User account for persona
    └──► save PostgreSQL [Persona + Prompt]


────────────────────────────────────────────────────────────────────────────────
 FLOW 4 — Attach Context Source to Topic
────────────────────────────────────────────────────────────────────────────────

  [User]
    │  POST /api/topics/{topic_id}/contexts/
    │  { type: doc|code, label, content, language }
    ▼
  [nexus-nucleus]
    ├──► save PostgreSQL [ContextSource]
    │
    │  POST /api/v1/embed/context/
    ▼
  [nexus-ai — EmbeddingManager]
    ├──► AdapterFactory.get(type)
    │       DocAdapter  → paragraph chunking (100–1000 chars)
    │       CodeAdapter → fn/class boundary splitting
    ├──► EmbeddingFactory → LiteLLMEmbedding → litellm.aembedding()
    └──► ChromaStore.store()
            collection_id returned
    │
    ◄── collection_id
  [nexus-nucleus]
    └──► save collection_id back to ContextSource


────────────────────────────────────────────────────────────────────────────────
 FLOW 5 — Normal Message (no @mention)
────────────────────────────────────────────────────────────────────────────────

  [React App]
    │  send message: "just chatting"
    ▼
  [nexus-nucleus]
    ├──► save message to PostgreSQL
    ├──► publish to Centrifugo [topic-{id}] → [React App sees message]
    │
    │  has no-context flag?
    ├── YES ──► skip embed — done
    │
    └── NO  ──► POST /api/v1/embed/message/ (fire & forget)
                  { message_id, topic_id, content, role, sender, tags,
                    message_number }
                ▼
              [nexus-ai — /embed/message/]
                ├──► LiteLLMEmbedding.embed(content)
                └──► ChromaStore.store()
                      collection: topic-{topic_id}-chat
                      metadata: { message_id, message_number,
                                  tags, sender, topic_id, role }


────────────────────────────────────────────────────────────────────────────────
 FLOW 6 — AI Trigger (@mention)
────────────────────────────────────────────────────────────────────────────────

  [React App]
    │  send message: "@Bot explain this"
    ▼
  [nexus-nucleus — @Mention Detector]
    ├──► detect @Bot → resolve to Persona
    ├──► no-context + @mention? → no-context IGNORED (@mention wins)
    ├──► save message to PostgreSQL
    ├──► publish to Centrifugo [topic-{id}] → [React App sees message]
    ├──► POST /api/v1/embed/message/ (fire & forget) ← always embeds
    │
    │  POST /api/v1/trigger/
    │  { persona_id, topic_id, user_id }   ← only these three
    ▼
  [nexus-ai — /trigger/ router]
    │
    ├──► [Authorization]
    │       GET /internal/personas/{persona_id}/
    │       ◄── { persona, prompt, model_config, mcp_servers[] }
    │       check user has rights to call this model
    │       → 403 if not authorized
    │
    ├──► has MCP servers?
    │       YES → AgentFactory → AgentRunner (pydantic-ai with MCP tools)
    │       NO  → LLMFactory   → LiteLLMModel (direct streaming call)
    │
    ├──► [AgenticManager.run(persona, topic_id, message, output_type)]
    │
    │       ▼
    │     [ContextManager] receives topic_id
    │       │
    │       │  GET /internal/topics/{topic_id}/contexts/
    │       │  ◄── list of attached context sources
    │       │  apply prompt.context_scope filter if defined
    │       │
    │       ├──────────────────────────────────────┐
    │       ▼                                      ▼
    │   [ChatContext]                  [DocContext / CodeContext / ...]
    │   always runs                    runs for each attached source
    │       │                                      │
    │       │  embed query (LiteLLM)               │  embed query (LiteLLM)
    │       │  search Chroma                       │  search Chroma
    │       │  collection: topic-{id}-chat         │  collection: {collection_id}
    │       │  → top-k relevant messages           │  → top-k relevant chunks
    │       │                                      │
    │       └──────────────┬───────────────────────┘
    │                      ▼
    │              rank + token budget → selected chunks
    │
    │       ▼
    │     [PromptBuilder.build()]
    │       │  system_prompt         (from persona prompt)
    │       │  output_type hint      (injected as format instruction)
    │       │  + context results     (from ContextManager)
    │       │  + current message
    │       │  → messages[] (OpenAI format)
    │
    │       ▼
    │     [LLMModel or AgentRunner]
    │       LiteLLM.acompletion(model, messages, stream=True)
    │       AgentRunner calls MCP tools if needed during run
    │       → tokens stream out
    │
    │  SSE: message_start → message_delta... → message_done
    │       message_done includes: { content, output_type,
    │                                tokens_input, tokens_output,
    │                                tokens_total, cost, latency_ms,
    │                                full_prompt }
    ▼
  [nexus-nucleus — SSE Consumer]
    │
    ├── message_delta ──► publish token to Centrifugo [topic-{id}]
    │                         ▼
    │                     [React App] renders token by token
    │                     frontend renders based on output_type
    │
    └── message_done  ──► save full AI response to PostgreSQL
                              sender = persona.user (shadow account)
                          ├──► save AIRequestLog (full audit)
                          └──► POST /api/v1/embed/message/ (fire & forget)
                                    embed AI response into Chroma

 MILESTONE 7.1 — Session Management
 Goal: Per-user timed AI sessions so multi-turn conversation works naturally
━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━

  DESIGN DECISIONS
  ────────────────
  @session is an inline modifier placed at the END of a normal message,
  not a separate command. Sessions are per-user + per-topic.
  User A's session never affects User B in the same topic.
  A session holds one or more active personas (all fire in parallel).
  Timer is FIXED from session open time — not activity-based.
  Default timeout comes from CompanyAIConfig.session_timeout_minutes.
  New @session always closes the existing session first, then opens a new one.

  SYNTAX EXAMPLES
  ───────────────
  "@NeuralOps explain this @session"
    → NeuralOps responds to this message + session opens with NeuralOps

  "@NeuralOps @TerminalBot analyze this @session"
    → both respond in parallel + session opens with both

  "explain this"  (while session active, no @mention)
    → all session personas respond in parallel

  "@TerminalBot run tests"  (while NeuralOps session is active)
    → ONLY TerminalBot responds — explicit @mention overrides session

  "@session close"
    → session closed, no AI trigger

  ROUTING PRIORITY (evaluated per message, per user)
  ──────────────────────────────────────────────────
  1. @session close         → close session, stop
  2. @mention + @session    → close old session, open new one with mentioned
                              personas, trigger mentioned for this message
  3. @mention (no @session) → trigger only mentioned personas,
                              session unchanged
  4. no @mention, session active + not expired
                            → trigger all session personas in parallel
  5. no @mention, no session → human-only message, no AI trigger

  RESERVED KEYWORDS (cannot be persona names)
  ────────────────────────────────────────────
  session, close  — plus existing output type keywords:
  text, code, chart, html, form, terminal, table, diagram

 MILESTONE 8 — MCP Integration
 Goal: Agent personas (model + MCP servers) work end-to-end
━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━

  DESIGN DECISIONS
  ────────────────

  PERSONA TYPES — how each is invoked in nexus-ai
    1. Plain model      source_type="model"
                        → persona.model → LiteLLM direct call (working today)
    2. Self-made agent  source_type="agent", agent_type="internal"
                        → persona.agent.model + persona.agent.mcp_server[]
                        → pydantic-ai Agent with MCPServer tools
    3. Online agent     source_type="agent", agent_type="external"
                        → persona.agent.external_url
                        → HTTP/SSE proxy — only final response visible to us
                          treated same as any AI message (save + embed)

  MCP IS NOT A CONTEXT MANAGER
    MCP servers are tool executors only — they run things and return results.
    Context management is the model's job + our ChromaDB RAG pipeline.
    MCP never decides what goes in the context window — the model does.

  MCP TOOL OUTPUT — TWO SIMULTANEOUS PATHS
    ├──► raw result → model context window (tool call loop, immediate)
    └──► embedding pipeline → ChromaDB (fire and forget, future retrieval)
    Embedded same as any message: role="tool",
    metadata: { tool_name, mcp_server_id, topic_id }

  MCP EMBEDDING RULES
    External/third-party MCP servers → NO embedding ever
    First-party marketplace MCP servers → opt-in PER TOOL (not per server)
    Developer configures embed_output when publishing to marketplace.
    MCPServer model fields:  is_first_party: bool
    MCPTool config fields:   embed_output: bool
    SSH/terminal/live-state tools → skip embedding (stale immediately)
    File reads, knowledge fetches → embed if opted in

  <<<EMBED>>> MARKER — HYBRID EMBEDDING DECISION
    Not all AI output is worth embedding. Embedding rules in priority order:
      1. User override ("Save to memory" / "Remove from memory" button) → wins
      2. render_as = "text" or "code" → embed automatically, no marker needed
      3. render_as = "html" / "form" / "terminal" → embed ONLY if model
         produces <<<EMBED>>> block describing what was generated
      4. No <<<EMBED>>> present + non-text render_as → skip embedding
    The <<<EMBED>>> + <<<END_EMBED>>> block is injected into system prompts
    for html/form/terminal output types only. The actual HTML is never stored.

    Example model response:
        <<<EMBED>>>
        Q1 2025 revenue chart. West region grew 40% YoY. Total $4.2M.
        <<<END_EMBED>>>
        <<<OUTPUT:chart>>>
        <!DOCTYPE html>...Chart.js page...
        <<<END_OUTPUT>>>

    parse_output_markers() updated to return THREE values:
        (clean_content, marker_type, embed_description)
        embed_description = text inside <<<EMBED>>> block, or None
